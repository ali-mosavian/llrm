# QB runtime on a host (#4669)

The QB runtime runs on a Linux or macOS host with SDL graphics, keys and sound. State: the device platforms and the
host runtime base are in; no QB program has been compiled for a 64-bit target yet, so tests call the runtime's own
entry points from C.

## Layout

```
runtime/shared/            OS layer (interface.toml: files, memory, process, console keys, time)
  dos/m16 dos/m32          the DOS implementations (unchanged)
  posix/                   os.c + llrm_os.h (rendered from interface.toml, `LLRM_BLESS=1 cargo test -p llrm-target`)
runtime/qb/                portable runtime; touches the machine only through runtime/qb/dev
  dev/interface.toml       the device ops: text, graphics (gd_*), keyboard, sound, timer, printer
  dev/dev.h gfxdev.h       their prototypes
  dev/dos/{m16,m32}        BIOS, VGA, speaker, clock (moved from runtime/qb/dos; same objects)
  dev/host/                video.c (framebuffer, palette, gd_*, dev_text_*), tick.c, vgadata.c (font, palettes)
  dev/headless/            scripted keys, tone log, virtual clock, PPM dump (tests)
  dev/sdl/                 present (window), input (events to keys), audio, sync (flush points), dev.c, host.c (main)
  posix/                   host platform glue: platform.h, xi.h, ad, block, startup, mathops, paintq
```

`tests/qb_dev_interface.rs` keeps the list, headers, platforms and portable code in agreement.

## Build and run

- SDL2 must be real SDL2 (2.30+), not sdl2-compat (Homebrew's default `sdl2-config`, on SDL3): it crashes on a pushed
  `SDL_TEXTINPUT`. On a Mac use `/opt/homebrew/Cellar/sdl2/<version>` with `SDL2_CONFIG` pointing at its `sdl2-config`.
- Tests: `cargo test --test qb_dev_interface --test qb_headless --test qb_sdl --test posix_os`. The SDL test needs SDL2:
  `SDL2_CONFIG`, `sdl2-config` on the path, or `tools/build-sdl2.sh` (private build in `~/.cache/llrm/sdl2`, dummy video
  and audio only, which the test selects with `SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy`).
- A host program links the portable runtime, `runtime/shared/posix/os.c`, `runtime/qb/posix/*`, `dev/host/*`, one device
  platform and, for sdl, `dev/sdl/host.c`, which supplies `main` and calls `qb_host_program(argc, argv)` on a worker
  thread. See `tests/qb_sdl.rs` for the file list and flags. `QB_SDL_HOLD=1` keeps the window after the program ends.
- Fonts and palettes: `python3 tools/gen_qbvga.py <dosbox-x source> > runtime/qb/dev/host/vgadata.c`.

## Checked against the source (the issue's [verify] items)

- `interface.toml` had no `screen_*`/`gfx_*`/`speaker_tone` ops; the device code was already in `runtime/qb/dos`.
- The portable runtime called DOS interrupts (`dev_int21` in DATE$/TIME$, `dev_int16` in event keys) and `dev_sincos`:
  now `dev_date/time(_set)`, `dev_key_peek_scan/discard` and `mathops.h`.
- String descriptor: `{uword len; char *ptr}`, so it widens with `uword` (16 bytes on a 64-bit host); the array descriptor
  likewise (the flat layout, words of the target). Not yet generated by the frontend for 64 bits.
- `abi/qb.rs` sets `i386: true` in its refinements: unchanged, the compiler side of the 64-bit work.
- NIBBLES uses no video segment or `PEEK`/`POKE`; GORILLA pokes the BIOS data area (`DEF SEG = 0`, NumLock at 1047). The
  other demos on tinytim have none. The m32 policy (warn and ignore) is enough for them; not implemented on the host.

## Deviations and gaps

- Tone: `dev_tone` is "a tone until the next call", so the SDL audio callback reads one atomic, not a queue.
- GET/PUT arrays have the DOS layout (checked by the oracle that the DOS device passes), but the 16-colour palette is the
  real EGA/VGA one, not DOSBox's: pixel values match DOS, RGB may not.
- SDL2 only (SDL3 later), dynamic. Not run: macOS arm64 (no such machine here), a real window (tinytim has no X11 or
  Wayland; the test uses the dummy drivers), the dirty-line protocol on arm64.

## Open rows (the issue's checklist against what landed)

1. macOS arm64: not built or run natively (arm64 Linux under qemu passes the headless tests: `tests/qb_arm64.rs`, sysroot from `tools/build-arm64-sysroot.sh`). Milestone 6, and the atomics/dirty-line stress on arm64 (test 4), are open.
2. Real window and real audio device: only the dummy drivers ran; no X11/Wayland/sound server on tinytim.
3. Audio: the callback is tested only for receiving the tone (`sdl_audio_current`), not for its samples; PLAY timing through
   SDL is untested (PLAY parse and timing are tested headless). No tone queue (see Deviations).
4. Keyboard: the queue and CP437 text/F/cursor keys work; Alt combos, Ctrl-Break and key-up (`STRIG`, `ON KEY` modifiers)
   are not mapped. Layouts are SDL text input's.
5. Interrupt hook: only the exit hook (`llrm_os_set_exit_hook`) exists. The DOS-only vectors/PSP/`chain` are not behind an
   interrupt hook, and the portable runtime has no host use for them yet.
6. Text-only device over the shared streams (console programs with no window): not written.
7. `display.wait_retrace`: not in the interface; `sleep` has no SDL flush hook (SLEEP and TIMER loops flush through
   `dev_clock` and `dev_key_ready`).
8. Rasterizer fast path (framebuffer pointer and pitch, measured against the per-op path): not done.
9. Present: lines are converted one by one and the whole frame copied; adjacent-line merging and the "most lines flagged"
   shortcut are not done, and no seqlock (tearing accepted, not observed).
10. POSIX-shaped op names: the DOS names are kept and mapped (`posix/os.toml`); no `wall` op (`local_time` instead).
11. Floating point: the host print/parse path against the DOS goldens (`SINGLE`/`DOUBLE`) is not compared.
12. Heap and addresses: a host `malloc` behind `$DYNAMIC` arrays and the 32-bit-addressable arena for `VARPTR`/`PEEK`/`POKE`
    are not done (milestone 7 and decision 1 of the issue).
13. Video-memory policy (milestone 7): chosen (warn and ignore, as m32), not implemented on the host.
14. Tests: headless runs PRINT, INKEY$, BEEP, SOUND, PLAY, TIMER, TIME$, DATE$ and the graphics statements, but not the
    existing string, error, `PRINT USING` and array suites; no NIBBLES/GORILLA goldens, no scripted GORILLA, no NIBBLES intro
    in the SDL smoke test. All need a QB program compiled for a 64-bit target (compiler side: `bitness`/`flat`,
    `native_contract`'s `i386: true`, ELF/Mach-O symbol names, 64-bit descriptors, none started).
15. Build: the host runtime is compiled by `cc` in the tests; it is not a static library with one object per module, and
    there is no macOS x86-64 build.
16. GORILLA and NIBBLES on x86-64 (`llrm-qb -m64`, ELF64; `PRINT "HELLO"` runs, `tests/qb_x86_64_host.rs`): wait on D64-4
    (SSE forms #4636, xmm class #4638, DAG float nodes #4678/#4643, S4, S5; `x86-64-dag-plan.md`). Also open here: the
    64-bit runtime frame (`B$ENRA`/`B$EXSA`), the `ON ERROR` landing (`qb_land` ends the program), the stack-block entries
    (`B$DDIM`, `B$CLOS`, ...). Retry when #4638 and S4 land.
17. arm64: `llrm-qb` has no route to the arm64 backend (code from MIR, QB data sections, Mach-O/ELF). A private aarch64
    sysroot (clang, lld, qemu-aarch64) can build and run ELF; Mach-O runs on a Mac only.
