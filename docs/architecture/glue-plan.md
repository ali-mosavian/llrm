# The glue between bodies: Stamp, Summaries and the interprocedural stage as LLVM's mechanisms

TL;DR: the code that carries what one body proves to the others (`Stamp` 108 M on d_faces -O2, `Summaries`, `Interprocedural`'s nine stages) is replaced by LLVM's own mechanism at `d1106deb71cc` or deleted; the order is stamp first, then the CGSCC walk, then one stage at a time. Owner: cgscc-poc. Nothing here is built yet.

## What there is

`Interprocedural` (`crates/opt/llrm-transforms/src/interprocedural.rs`, 2,163 lines) runs once every body has reached its own fixed point and sends each changed body back through the pipeline. Its stage 1 and 9 are `Stamp`/`stamped_all`: the memory, capture and termination attributes of every body, callees first. `Summaries` (`ModuleAnalysis`, `manager.rs`) is each function's memory effects by name, read by about a dozen passes and analyses (`alias`, `memoryssa`, `dse`, `gvn`, `hoist`, `fold`, `loadjoins`, `homes`, `settled`). The cost: `Stamp` is 108 M in three runs on d_faces -O2, 88 M of it `alias::initialized` on the 9 bodies that write through a pointer parameter ([compile-time-spec.md](compile-time-spec.md)).

LLVM has no module-wide summary table and no whole-program step. A function's effects are attributes on the function (`memory(...)`, `nocapture`, `willreturn`, ...), set by `PostOrderFunctionAttrs` as the CGSCC walk reaches each SCC, and read where a pass asks the alias analysis about a call. A change reports what it kept (`PreservedAnalyses`) and the manager drops the rest. Bodies are revisited by the walk (`DevirtSCCRepeatedPass`), not by a stage list.

## Order

1. (memory half: `functionattrs::infer_memory` is the translation of `addMemoryAttrs`, in shadow behind `LLRM_SHADOW_MEMORY`; `argumentattrs::add_argument_attrs` is `addArgumentAttrs` without `initializes`, and `functionattrs::post_order` runs both with the flags, same switch; they wire in with the walk, since LLVM states it after the SCC's bodies are simplified and `Stamp`'s first run sees raw bodies.) `PostOrderFunctionAttrs` as a pass over an SCC, behind a flag, oracle: `opt -passes=function-attrs` on the dumped module (basicaa-port's `capturecheck` for `nocapture`, #2146). Replaces `Stamp`; the slope test is the stamping cost against N bodies.
2. `Summaries` readers move to the AA queries; `Summaries` deleted (one PR per reader, rows-neutral).
3. The walk (`PreservedAnalyses`, `DevirtSCCRepeatedPass`) around inline and function-attrs; blocked by [step 3.2 of the order work](cgscc-plan.md).
4. `ipsccp` replaces stages 4, 5a, 6; `deadargelim`, `argpromotion` diffed.
5. Delete 8, 9a, 9b, then the stage list.

Each step is its own PR with the LLVM permalink, the rows line with the premise count, and a slope test: any super-linear step needs a stated reason.
