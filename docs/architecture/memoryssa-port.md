# MemorySSA as a translation of LLVM's: the plan

TL;DR: `MemorySSA.cpp` and `MemorySSAUpdater.cpp` (4,213 lines at `d1106deb71cc`) are translated into a new module, function for function, beside today's `memoryssa.rs`; the walker and the updater are the parts llrm lacks (it rebuilds the graph per body version and walks from the site per query). Shadow first: the translated walker answers every query the old one answers on the dumped inputs, and the build and the walk are costed per IR instruction against LLVM's on the same bodies.

Pinned: LLVM [`d1106deb71cc`](https://github.com/llvm/llvm-project/tree/d1106deb71cc81016406a1917d0508d2df296266), llrm main at the time of writing. Rules for the code: the API is LLVM's (`MemoryDef`, `MemoryUse`, `MemoryPhi`, `LiveOnEntry`, `getDefiningAccess`, per-block access and def lists in order, the walker and updater signatures), so EarlyCSE, LICM and DSE client code translates line for line; dense ids and `Vec` are a representation under that API, not a change to it. Each Rust function is a translation of the C++ function named in its first comment (permalink), in the same order of checks, with the `cl::opt` defaults for every cap; anything not translated is a DEVIATE with a reason and a number.

## 1. What differs today, measured (`d_faces` -O2)

| | LLVM (clang 24) | llrm main |
|---|---:|---:|
| graph build | `MemorySSAAnalysis::run` 2.47 M, 27 builds | `structure_of` 57.6 M, 93 builds (62% over a body whose memory ops and CFG changed) |
| kept across edits | `MemorySSAUpdater` per edit | rebuilt; `Accesses::update` keeps the structure only when no memory op or terminator changed (15.7% of the weight) |
| walker queries | 286 `getClobberingMemoryAccess`, about 11,000 each, cap `memssa-check-limit` 100 | 4,787 frontier queries, 27,750 each; step cap 1,000, candidate cap 100 (#2068, #2083) |
| result stored in the access | `OptimizeUses`: each use holds its clobbering def | none |
| alias query | `AAQueryInfo` cache per query object | `may_clobber`, 884 per slow call, a cache only inside the walk |

Sources of the numbers: docs/comparison/llvm/memoryssa.md, and [dse-poc](dse-poc.md) for the build and the alias-pair counts.

## 2. Translation map

Rust module: `crates/opt/llrm-analysis/src/mssa/` (`access.rs`, `build.rs`, `walker.rs`, `updater.rs`, `verify.rs`); `memoryssa.rs` stays until the shadow run is clean, then its walker and structure are replaced by the module.

From the structure-updater probe: the non-CFG edit sets that rebuild the graph today only erase (27) or rewrite (53) memory ops; no inserts, no moves.

## 3. Shadow measurement

On the dumped inputs (`~/scratch/replay/inputs-base`, `inputs-exp`, and the replay set) the translated build and walker run beside today's, never in the pipeline:

1. Equality: for every load and store of every body the translated `getClobberingMemoryAccess` is one of today's `clobbers` set (or its phi optimum) with the same caps; any difference is classified (cap, a fact LLVM lacks, a bug).
2. Cost: `build_memory_ssa` instructions per IR instruction against LLVM's `MemorySSAAnalysis::run` on the same function bodies (2.47 M over 27 builds; the bodies from `-print-before=memoryssa`-style dumps of `clang -cc1`), and walker steps per query against LLVM's 286 queries at about 11,000.
3. Updater: after every edit the updated graph equals a fresh build (`LLRM_CHECK_MEMORYSSA`), on the dse, gvn and hoist runs' real edits replayed from the inputs.
