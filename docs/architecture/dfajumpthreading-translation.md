# DFAJumpThreading as a translation of LLVM's: the plan

TL;DR: `DFAJumpThreading.cpp` (1,579 lines, pin `d1106deb71cc`) becomes a new `dfajumpthreading.rs` in three slices (about 1,300 + 350 + 150 lines); the registry row `dfa-jump-threading` is Missing, owner parity-pipeline. The old `jumpthread.rs` is deleted whole after S1–S3: its switch half is DFAJumpThreading's, the branch half is JumpThreading's, and `split_arms` is parity to drop at -O2/-Os (section 4).

Rule for the code: each Rust function is a translation of the C++ function named in its comment (permalink at the pin); what is not translated is a numbered DEVIATE (`DF1`, `DF2`, ...) in the module header. Idiomatic Rust, no machine facts in the pass: the limits are fields of a `DfaJumpThreadingOptions` (defaults are the pin's values, as `JumpThreadingOptions` does), costs come from `CodeMetrics` and the TTI trait (`crates/ir/llrm-mir/src/tti.rs`). Near O(n): the pin's caps are the bound, kept as they are; a step beyond them needs a stated reason and a slope test at 1x and 4x.

## 2. What exists, what is missing

Exists: `CodeMetrics` and `collect_ephemeral_values` (`codemetrics.rs`), `clone_block`/`ValueMap` and `set_block_name` (`edit.rs`), `LoopInfo` with `get_outermost_loop`, the iterated dominance frontier (`idf.rs`). Done with S1: T1 `Tti::estimated_number_of_case_clusters` (`tti.rs`; `inlinecost.rs` calls the same default), T2 `SSAUpdaterBulk`.

Done with S3: T3 `LoopInfo::add_basic_blocks_to_loop` (`loopinfo.rs`; `Loop::addBasicBlockToLoop`, for the blocks of one loop at once), used by `unfold`. The loop info is not kept across the clones themselves: the pin keeps it unless it cloned (`LoopInfoBroken`), here the manager drops it on change (DF2).

## 3. Slot and registry

`DFAJumpThreadingPass` runs once per function in the function simplification pipeline at [`PassBuilderPipelines.cpp#L806`](https://github.com/llvm/llvm-project/blob/d1106deb71cc81016406a1917d0508d2df296266/llvm/lib/Passes/PassBuilderPipelines.cpp#L806), right before `JumpThreadingPass` (`jumpthreading@809`), under `enable-dfa-jump-thread` (default on); slot `dfajumpthreading@806`, absent at -O1, 3 runs on `x_hanoi2` and 11 on `d_faces` (`parity-pipeline-slots.md`), skipped for `optsize` functions. The registry row `dfa-jump-threading` (Simplify, Missing) became Partial `dfajumpthreading@806` with S1 (the key is the pass's name, as every slot's) (criterion: identical to `opt -passes=dfa-jump-threading` on the corpus inputs; exit: the old `jumpthread.rs` switch half deleted) and Translated after S3. On by default from S1 under `llvm_order`, off with `LLRM_NO_DFAJUMPTHREADING` (set).

## 4. The old `jumpthread.rs` (1,370 lines, 31 tests)

It runs once per body after the loop passes (`pipeline.rs`, `wanted("jumpthread")`), not at the pin's position. It does four jobs; DFAJumpThreading replaces the first:

- **Switch on a state phi** in a loop (the `DFAJumpThreading` shape). Tests by name: the switch-on-state, two-joins, several-edges and three-edges cases (`jumpthread_tests.rs`) become oracle cases; the `found` twice test (#2700) too.
- **Branch on an `i1` phi or a compare of a phi** and the correlated branch: JumpThreading's `processBranchOnPHI` and threading (S2 of `jumpthreading.rs`, on by default); the branch tests are JumpThreading oracle cases, not DFA's.
- **`split_arms`** (a loop branching on an invariant gets a loop per arm): no DFA counterpart; the pin's is non-trivial `simple-loop-unswitch`, which runs only at -O3 ([`PassBuilderPipelines.cpp#L733`](https://github.com/llvm/llvm-project/blob/d1106deb71cc81016406a1917d0508d2df296266/llvm/lib/Passes/PassBuilderPipelines.cpp#L733): `NonTrivial = Level == O3`). At -O2/-Os it splits loops where the pin never does, so deleting it there is parity. Any -O3 loss is row DF6 (section 6).
- **gcc's limits** (`MAX_PATH` 100, `MAX_COPIED` 400, tuned-for-size) and the cleaning sandwich after a thread (`fold`, `algebraic`, `decide`, `dead`): replaced by the pin's cost model and by the pass returning its preserved set; the gcc-limit test is stale.

Retire plan: after S1 is oracle-identical on the corpus kernels that use the switch half (QCport `triggers`/`ent_trig_shot`, the switch programs) the switch code is deleted from `jumpthread.rs` (a `Deletes:` line). The branch half goes with JumpThreading's flip (done). So `jumpthread.rs` is deleted whole after S1–S3 alone (done: alim/feat/del-old-jumpthread; its xfail #3018 went with it); it does not wait for non-trivial `simple-loop-unswitch`.

### No interim shortcut

`JumpThread::run` calls `fold`, `algebraic`, `decide` and `dead` directly after `analyses.invalidate(none)` (`jumpthread.rs:237-245`). Call edges on one binary (d_faces -O2 `-fno-inline-functions`, head `aa14375fc`): 72.74 M inclusive = Decide 29.67 + Fold 28.48 + Algebraic 8.12 + Dead 0.94 + `threaded` 5.41, over 11 calls that change one function (198 to 181 blocks; 43 changed or new, 17 removed).

None of the four passes has a block filter or scope: each runs whole-function fixed-point rounds. Skipping the sandwich changes 20 objects over the corpus (`compile-time-spec.md`). Decision: no shortcut and no preserve-DomTree/loops prototype; the old pass retires with S1–S3. Bench's own split (38.1 M exclusive + 24.6 M nested) did not match these call edges.

## 5. Staging

- **S1 (about 1,300 lines):** options, `run`, `MainSwitch` without select unfolding, all of `AllSwitchPaths`, `TransformDFA` whole (legality, cost, clones, SSA by DF2), the slot and the oracle `dfajumpthreading` in `tools/difftest` against `opt -passes=dfa-jump-threading`. Fail-first tests: one per stage (a candidate, a path set, the cost refusal, a clone, an outer use).
- **S2 (about 350 lines, done):** `unfold` and the select worklist (`dfajumpthreading/unfold.rs`, about 300 lines); closes DF1, adds DF4; a size build threads nothing (`hasOptSize`).
- **S3 (about 150 lines, done):** the loop-info update (T3) in place of the rebuild, closes DF4; `SSAUpdaterBulk` (T2) came with S1; registry to Translated.

Estimate for S1: about one day of fork time after this note lands (JumpThreading S1, 1,950 lines, took about one day; S2 and S3, 1,050 lines, about one day). A date follows when S1 is open.
